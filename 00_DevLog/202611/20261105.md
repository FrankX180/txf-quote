## 內外盤改走 Yahoo 三檔主線（11:30）

### 問題現象
11/04 深夜發現站上內外盤在小台、微台爆量時漏抓：21:15~21:24 分鐘序列斷 9 分鐘，小台漏 6.3%、微台漏 20.3%，而自動對帳只拿大台對 MIS 總量，因此仍顯示 ok。老公拿元大投資先生截圖比對後要求徹底解決資料源。當晚先修分頁 bug、改 Yahoo 主線，後續又清掉口徑接縫、移除會污染序列的富邦備援，並在副圖標題加註「大+小+微」。

### 根因／決策理由
根因是 Worker syncImb3 的分頁游標在第 0 頁就把 serial 推進到最新，第 1 頁以後永遠判定「全是舊資料」提前 break，每分鐘每檔最多抓 500 筆；大台量小無感，小台微台爆量就掉資料。架構上「逐筆增量累加」遇斷線必然要補洞；而 Yahoo StockServices 的 inMarket/outMarket 是期交所端當盤累計狀態值，一個請求三檔齊全、斷線不漏，故改為 Yahoo 主線。後續發現兩個口徑問題必須處理：Yahoo 回傳的是千口小數（33.191＝33,191 口），且日盤累計含前一夜盤；另外富邦逐筆自行分類會比官方多約 2%，一旦插進 Yahoo 序列就會跳升後回落，因此備援改為不寫入。

| `yahoo-quote.js` | 新增 syncImb3Yahoo（三檔合計、千口換算、日盤扣前夜基期、基期未追上則跳過該分鐘），Yahoo 缺值不再 fallback 寫入富邦，imb3 寫入失敗獨立 try 不拖垮報價 |

### 口徑對齊（可追溯）

11/04 夜盤 15:00~01:51 共 652 根原本是富邦逐筆自行分類（每筆都給方向），總量比 Yahoo 官方多約 2%；01:52 之後改由官方 inMarket/outMarket 寫入，兩種口徑直接相接會在 01:51→01:52 掉 5 萬（微台口），看起來像忽然大量賣出。處理：對前段套用線性比例 in×0.98249、out×0.97569（＝前段最後一根與 01:52 官方值的比），使接縫連續；內外盤比例不失真、只縮總量。要還原原始富邦值：`python scripts/imb3_backfill.py --day 20261105 --session night`（會用交易所逐筆重算並覆寫），但接縫會重新出現 2% 落差。

## 即時報價來源釐清與前端先畫修正（21:45）

### 問題現象
夜盤前端卡在「載入中」，最初誤判為網站掛掉。追查後確認頁面與靜態資料都正常，卡住的是報價 API 抽風；再往下查發現即時價其實走瀏覽器直連期交所推流，與 Cloudflare 出口無關，手機在外也適用。

### 根因／決策理由
前端 applyMisOverlay() 第一行是 if (!snap) return；當快照檔與 Worker 都沒回來時 snap 恆為 null，即使期交所推流已經在跳，畫面仍寧可空白，這才是「有價卻不顯示」的真因。另外期交所 MIS REST 對 Cloudflare 出口回 520，只影響後端校準，靠 Yahoo 與瀏覽器直連即可頂住，因此不需要改接代理（Workers 也不支援 proxy 隧道）。
