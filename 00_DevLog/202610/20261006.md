# 2026-10-06 開發日誌

## 1. 任務背景與問題定位
- **起點**：GitHub Actions 連續寄出 `fubon-imb` 失敗通知（`FrankX180/txf-quote`，master `a392fe3`）。`guard` 6 秒綠、`fill` 33 秒紅。
- **表面真因**：`scripts/fubon_imb_fill.py` 補值寫入的 UPSERT SQL 拋 `ValueError: unsupported format character ' ' (0x20) at index 135`。
- **深層真因**：那行把整段 SQL 拿去做 Python `% OWN` 格式化，而 SQL 裡的模除運算子 `imb.ts % 60000` 被 Python 當成格式字元（`%` 後接空白）→ 直接爆。
- **為何「突然」連發**：該段只在**偵測到缺口**（`gaps > 0`）時才執行；先前 run 都 `gaps 0` 直接 return，今天 11:00 出現缺口才首次走到，於是每輪重試皆紅。屬「條件觸發才炸」的潛伏 bug，平常 CI 全綠是假安穩。

## 2. 影響面
- 內外盤缺口補值停擺（今天 11:00 那格補不進 D1）；D1 其餘寫入（Worker / `update-quote`）不受影響。
- 信箱被失敗通知刷頻。

## 3. 修法與交付
