# 2026-10-07 FuturesHTML 開發日誌

## 主題一：MIS 官方開高低／漲跌停落地（fetch_quote.py）

### 背景
老公發現 `E:\_Project\股票資料庫\資訊來源API\API參考\API參考_TAIFEX_MIS期貨行情.md`，提問「MIS 是不是更適合取代網頁端報價」。
查證結論：**MIS 早就在用**——`fetch_quote.py` 與 `worker/yahoo-quote.js` 都打 `getQuoteList`，但只拿它覆蓋一個即時價，其餘官方欄位全丟。

### 問題
- `apply_mis()` 只覆蓋 6 欄（price/bid1/ask1/change/rate/ref/vol/time），MIS 的 `COpenPrice/CHighPrice/CLowPrice/CCeilPrice/CFloorPrice` 白給不用。
- 開高低繞道 `ohlc_from_kline()` 去打 Yahoo 1 分 K 回填（重複工 + 夜盤前綴風險）。
- 實測補證：夜盤 MT=1 回的 J6 合約開高低是**當盤純值**（開 49946/高 49946/低 49547，`CDate`=當日），可直接信。

### 交付
- `apply_mis()` 追加覆蓋 MIS 官方 `COpenPrice/CHighPrice/CLowPrice` → 存中間鍵 `misOpen/misHigh/misLow`，以及 `CCeilPrice/CFloorPrice` → `misCeil/misFloor`。
- `slim()` 由中間鍵映射出 snapshot 的 `COpenPrice/CHighPrice/CLowPrice/CCeilPrice/CFloorPrice`。
- `ohlc_from_kline()` 改為「MIS 無值才 fallback」，不再無條件覆寫官方值。

## 主題二：self-scan 修自身迴歸（盤別防護）

### 問題
第一版改動讓 `apply_mis` 無條件寫入 OHLC。但日收後～夜開前（13:46–14:57）`sess_now` 回 `None`，`_mis_quote` 會 fallback 抓夜盤（MT=1），夜盤開高低會被寫進 `q` 並繼承給 `day_q` → **日盤開高低被夜盤值污染**。原版 `COpenPrice=""` 靠 kline 回填是安全的，此為本次改動引入的迴歸。

### 交付
- `_mis_quote()` 成功時在 quote 上附 `_mt`（實際 MarketType）/`_want`（目標盤別）。
- `apply_mis()` 改為僅在 `sess in ("day","night") and _mt == _want` 時才寫入 OHLC／漲跌停；休市與 fallback 情形交給 kline 回填。

### 驗證
`scripts\fetch_quote.py` 實跑（夜盤）：`night OHLC 49946 49946 49540 last 49584 ceil 54964 floor 44972`，五檔 5 檔完整、`levels 5`。

## 主題三：AKO 顧問團 — 架構優化與 MIS 採用度

- 題目書：`E:\_PluginTools\.ako\2026_AKO\2026-10\futureshtml-arch-optimize\prompt.txt`
- 派 4 席（Opus4.6 / Grok / DeepSeek / Astra6，一席一 native subagent、`read`、各帶 model）；落檔 `grok.md`/`deepseek.md`/`astra6.md`（opus 首派逾時，重派中）。
- 三席共識：
  1. **H1（MIS 盡量採用）半對**：「較不易擋 IP」是偽命題，MIS 自己掛 Cloudflare，高頻 520 有實例（§9.1）。MIS 已在唯一該在的位置（覆蓋當盤價）。
  2. **H2（MIS 取代 Yahoo）否決**：Yahoo 是「五檔 + 內外盤」唯一源；MIS REST 只有買一賣一、無 in/out 欄位。
  3. **H3（K 線聚合）方向**：不是找新源，是收斂「單一時間軸 + 單一 bar schema + 單一裁決規則」；做「填洞」不做「選邊」，熱 D1 / 冷 Pages 分工正確。
- 關鍵新發現：
  - **覆蓋規則雙寫已語意分岔**（PY 存 `misOpen` vs Worker 存 `regularMarketOpen`）→ 可能靜默輸出不同結果。
  - **同一分鐘兩條真相**：HTTP 報價路徑有 MIS 覆蓋，Cron `pollAndStore` 寫 D1 卻只打 Yahoo。
  - **說明書成本前提錯誤**（Astra6）：Cloudflare 快取 HIT 仍計請求數（僅省 CPU）；100 持續看盤分頁約 137 萬次/日 > 免費 10 萬。
  - `volume` 單位不一致（`v*1000` vs 原始值）→ 1000 倍誤差風險。
  - 盤別邊界 14:55 / 14:58 / 15:00 三套並存。
- 建議第一步（未動）：覆蓋規則單一化 + golden test 止血。
