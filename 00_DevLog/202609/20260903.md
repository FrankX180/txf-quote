# 2026-09-03 FuturesHTML 工作日誌

## Cloudflare D1 rows_read 超限防護與架構優化（v2.19）

### 問題現象
收到 Cloudflare 警報信件，D1 免費方案每日 5,000,000 rows_read 已達 90% 上限，即將超標斷線。

### 根因分析（G38F 掃描 + 12 席 AKO 顧問對抗評估）
1. **流量統計全表掃描**：`handlePing` / `loadStats` 在每次 ping（每 2 分鐘或開頁）時執行 `SELECT COUNT(DISTINCT sid) FROM traffic_sid`，隨著歷史紀錄累積，單次查詢需掃描數萬筆 row，導致 rows_read 呈指數型累積。
2. **熱門資料缺乏 Worker 記憶體防護**：`loadPricePack`（1分K）與 `loadPack`（大單內外盤）每次請求皆直穿 D1 查詢數百至千筆，多用戶同時連線時造成大量重複讀取。
3. **DDL 重複執行**：`ensureSchema` 在每次 DB 操作前重複執行 8 次 `CREATE TABLE IF NOT EXISTS`。
4. **缺少關鍵複合索引**：`price_1m`、`imb`、`traffic_sid` 缺少查詢專用複合索引。
