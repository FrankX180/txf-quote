## 重構 D1 查詢與快取機制以解除斷線危機
- 需求：收到 Cloudflare 警報信件，D1 免費方案每日 5,000,000 `rows_read` 已達 90% 上限，即將超標斷線。
- 真因：
  ① G38F 掃描與 12 席 AKO 顧問對抗評估發現流量統計全表掃描：`handlePing` / `loadStats` 在每次 ping（每 2 分鐘或開頁）時執行 `SELECT COUNT(DISTINCT sid) FROM traffic_sid`，隨歷史紀錄累積致單次查詢需掃描數萬筆 row，使 `rows_read` 呈指數型累積。
  ② 熱門資料缺乏 Worker 記憶體防護：`loadPricePack`（1分K）與 `loadPack`（大單內外盤）每次請求皆直穿 D1 查詢數百至千筆，多用戶同時連線造成大量重複讀取。
  ③ DDL 重複執行：`ensureSchema` 在每次 DB 操作前重複執行 8 次 `CREATE TABLE IF NOT EXISTS`。
  ④ 缺少關鍵複合索引：`price_1m`、`imb`、`traffic_sid` 缺少查詢專用複合索引。
- 動作：
  ① 於 `worker/yahoo-quote.js` 中將 `ensureSchema` 加入單例標記 `_schemaEnsured`，並補齊 4 組複合索引。
  ② 於 `worker/yahoo-quote.js` 中將 `handlePing` 改為 `INSERT ... ON CONFLICT DO NOTHING` 冪等寫入，杜絕 `SELECT 1` 查表。
  ③ 於 `worker/yahoo-quote.js` 中將 `loadStats` 移除 `COUNT(DISTINCT sid)` 全表掃描，改以 `traffic_day` 聚合欄位匯總並加 5 分鐘記憶體快取 `_cachedStatsAgg`。
  ④ 於 `worker/yahoo-quote.js` 中對 `loadPricePack` 與 `loadPack` 引入 4 秒記憶體快取，合併同 isolate 併發查詢。
  ⑤ 於 `worker/yahoo-quote.js` 中將 `px1m` 與 `imb` CDN 快取設定調整為 5 秒。
  ⑥ 於 `index.html` 將頁腳版本與 `purgeOldMinCache` 升級為 `2.19`。
  ⑦ 於 `00_DevLog/202609/20260903.md` 記錄根因分析、修復項目與驗證結果。
  ⑧ 執行 Worker 語法檢查，透過 `scripts/deploy_worker.py` 成功部署至 Cloudflare。
  ⑨ 升級版本號至 2.19，提交並推送至 GitHub `master`。
