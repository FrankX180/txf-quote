# 2026-09-04 FuturesHTML 工作日誌

## Cloudflare D1 讀取額度優化與 Edge Cache 最佳架構升級

### 問題現象
- Cloudflare Dashboard 警告 D1 Rows Read 達到 1.91M / 5M（約 38.2% 累積量），前端高頻請求分 K 與內外盤可能導致每日限額超標。

### 根因分析
1. 前端 `index.html` 內外盤補齊計時閘雖然註解為 30 秒，但程式碼中誤寫為 `10000ms`（10 秒），導致前端每 10 秒打一次 `?kind=imb`。
2. Worker 端的 `?kind=px1m` 與 `?kind=imb` 在收到請求時直接執行 SQL 查詢當日資料表（每次讀取 500~1000 列），未在 Cloudflare 邊緣層進行全局快取攔截，造成多用戶或多分頁下 Rows Read 迅速累積。

### 修正內容

| # | 檔案 | 修正內容 |
|---|---|---|
| 1 | `index.html` | 修正 `loadImbCloud` 節流為 30 秒（`> 30000`）；版本號由 2.19 升級至 2.20，清理舊版分 K 快取。 |
| 2 | `worker/yahoo-quote.js` | 整合 Cloudflare 原生 `caches.default` (Edge Cache API)，對 `?kind=imb` 與 `?kind=px1m` 套用 8 秒邊緣共享快取（`s-maxage=8`）。全球用戶在 8 秒內共用快取，將 D1 查詢率降低 90% 以上。 |

### 技術細節
- **Edge Cache API 機制**：
  ```javascript
  const cacheKey = new Request(url.origin + url.pathname + "?kind=" + kind + "&day=" + day, request);
  const cache = caches.default;
  let cachedResp = await cache.match(cacheKey);
  if (cachedResp) return cachedResp;
  // 未命中才查 D1，並以 ctx.waitUntil(cache.put(...)) 存入邊緣快取
  ```
