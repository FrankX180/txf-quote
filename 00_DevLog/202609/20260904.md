## 導入 Edge Cache 與拉長請求間隔以降低 Cloudflare D1 讀取量
- 需求：解決前端高頻請求分 K 與內外盤可能導致每日限額超標之問題，控制 Cloudflare D1 Rows Read 累積速度。
- 真因：
  ① 前端 `index.html` 內外盤補齊計時閘雖然註解為 30 秒，但程式碼中誤寫為 `10000ms`（10 秒），導致前端每 10 秒打一次 `?kind=imb`。
  ② Worker 端的 `?kind=px1m` 與 `?kind=imb` 在收到請求時直接執行 SQL 查詢當日資料表（每次讀取 500~1000 列），未在 Cloudflare 邊緣層進行全局快取攔截，造成多用戶或多分頁下 Rows Read 迅速累積。
- 動作：
  ① 在 `index.html` 修正 `loadImbCloud` 節流為 30 秒（`> 30000`），並將版本號由 2.19 升級至 2.20，清理舊版分 K 快取。
  ② 在 `worker/yahoo-quote.js` 整合 Cloudflare 原生 `caches.default`（Edge Cache API），對 `?kind=imb` 與 `?kind=px1m` 套用 8 秒邊緣共享快取（`s-maxage=8`），全球用戶在 8 秒內共用快取將 D1 查詢率降低 90% 以上；實作邏輯為：
  ```javascript
  const cacheKey = new Request(url.origin + url.pathname + "?kind=" + kind + "&day=" + day, request);
  const cache = caches.default;
  let cachedResp = await cache.match(cacheKey);
  if (cachedResp) return cachedResp;
  // 未命中才查 D1，並以 ctx.waitUntil(cache.put(...)) 存入邊緣快取
  ```
  ③ 維持 Worker 代理架構，避免瀏覽器直接打 Yahoo 遭到 CORS 阻擋或 IP 限速封鎖。
