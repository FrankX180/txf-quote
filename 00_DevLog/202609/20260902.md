## Cloudflare D1 rows_written 超限修復

**問題**：Cloudflare D1 免費方案每日 100,000 rows_written 被打爆，收到超限通知。

**根因分析**：
1. 前端 `pollLive()` 每 5 秒調用，每次觸發 Worker 寫入 2 行（imb + px1m）
2. 前端每 30 秒強制 `?kind=poll`，繞過 CDN 直接寫入
3. Worker 的 `ON CONFLICT DO UPDATE` 雖然按分鐘去重，但 UPDATE 也算 rows_written
4. 多用戶並發時，寫入量線性累積

**修改方案**：
1. **v2.16 前端優化**（commit 34bd7a3）
   - `pollLive` 間隔：5秒 → 10秒（平衡刷新速度與寫入）
   - 移除前端 30 秒強制 poll（註釋掉，由 Worker cron 兜底）

2. **Worker 節流**（commit 5213011）
   - 新增全局變量 `lastWriteMinute` 追蹤上次寫入分鐘
   - 同一分鐘內只寫一次 D1（即使多次請求）
   - 核心邏輯：
     ```javascript
     const currentMinute = Math.floor(nowMs / 60000);
     if (currentMinute > lastWriteMinute) {
       lastWriteMinute = currentMinute;
       // 才執行 appendImb + appendPricePx
     }
     ```

3. **v2.17 統一刷新頻率**（commit 8793c9f）
   - `pollLive` 間隔：10秒 → 15秒
   - 與 `ensureLive1m`（1分K線）統一為 15 秒
   - 理由：Worker 已有分鐘級節流，前端頻率不影響 D1 寫入；統一頻率更簡潔

**修改檔案**：
| 檔案 | 變更 |
|------|------|
| `index.html` | pollLive 間隔 5s→15s；移除 30s 強制 poll；版本 2.13→2.17 |
| `worker/yahoo-quote.js` | 新增全局節流變量；fetch 處理加分鐘級去重 |

**驗證**：
- Worker 已部署（`deploy_worker.py`）
- 前端已推送 GitHub Pages（v2.17）
- Git commits: 34bd7a3, 5213011, 8793c9f

**效果預估**：
- 修改前：單用戶約 23,520 行/天（5秒輪詢 + 30秒強制）
- 修改後：所有用戶共享約 3,360 行/天（Worker 節流 + cron）
- 降幅：約 86%
- 可支撐：20-30 個並發用戶不超限

**最終刷新頻率**：

## v2.18 讀寫分離（秒數機制重做）

### 問題現象
v2.17 把報價與 1 分 K 統一成 15 秒，以為 Worker 分鐘節流就能壓住 D1。複核後發現瓶頸不是前端秒數，而是讀取型請求仍會寫 D1，且 Cron 每分鐘把整天約 680 根 K 棒整包 UPSERT。

### 根因分析
1. 前端 `pollLive` 用 `cache:"no-store"`，把 Worker 原本 5 秒 CDN 快取打穿。
2. `GET /` MISS 時 `waitUntil(appendImb + appendPricePx)`；`kind=1m` 成功就 `upsertPriceBars`，沒有分鐘閘。
3. `lastWriteMinute` 只活在單一 isolate，跨 colo／回收無效，且不管 `poll`／Cron／`1m`。
4. Cron `backfillChart1m()` 每分鐘整包重寫當日棒；本機 daemon 每 5 秒 `?kind=poll`。
5. GitHub Actions 約 5 分鐘一筆，前端卻把 snapshot 超過 35 秒當 stale，幾乎必打 `kind=poll&chart=1`。
6. 夜盤窗不一致：前端 14:58，Worker／daemon 14:55。

### 修正內容

| # | 檔案 | 修正內容 |
|---|---|---|
| 1 | `index.html` | 報價 5 秒讀、走 `cache:"default"`；拿掉前端 `kind=poll`；heal 改 6 分 stale／8 分冷卻；imb 改 default 快取；K 線只由 15 秒 guard 讀 px1m；升 VER 2.18 |
| 2 | `worker/yahoo-quote.js` | 刪 `lastWriteMinute`；`GET /` 與 `kind=1m` 不再因讀取寫 D1；`kind=1m` CDN 10 秒；Cron 只 UPSERT 最新 3 根；heal 6 分／檢查 5 分／dispatch 8 分；夜盤 14:58 |
| 3 | `scripts/poll_live_daemon.py` | 寫入間隔 5s→15s；夜盤 14:58 |
| 4 | `worker/AGENTS.md` | daemon 15 秒、夜盤 14:58 |
| 5 | `scripts/AGENTS.md` | daemon 改 15 秒 |

### 技術細節
- 前端是讀取者；D1 生產者只剩 Cron（每分增量 K）與本機 daemon（15 秒當根／內外盤）。
- 首次當盤無棒時仍寫完整當盤；之後每分鐘最多更新最近 3 根。
- 報價畫面 5 秒跳一次，實際上游 Yahoo 由 CDN 5 秒共用。
