# 2026-09-30 開發日誌

## 1. 任務背景與問題定位
- **起點**：GitHub Actions 通知 `update-quote` workflow 失敗，`guard` 成功、`fetch` 紅燈（7 秒即掛）。
- **表面真因**：`scripts/fetch_quote.py` 呼叫 Yahoo `StockServices.stockList`（`symbols=WTX%26,WCDF%26,WCCF%26`）回 **HTTP 500**（body `{"message":"request failed"}`）。
- **放大原因**：`Fetch Yahoo WTX quote` 這步**沒有 `continue-on-error`**（其他 fetch 步都有），一發 500 就整條 job 掛掉，連已抓到的 vix／imb／kline 都不 commit。
- **深層真因（本輪關鍵）**：此 500 是 **按來源 IP 選擇性** 的——
  - 本機（台灣 IP）打 → 500（`probe_yahoo.py` 連 4 次全 500）。
  - GitHub Runner（Azure IP）打 → 500。
  - 第三方 `web_fetch` 打 → 500。
  - **自家 Cloudflare Worker（`wtx.blok.trading`）打同一支 URL → 200，且回得到即時值**。
  - 即 Yahoo 未全掛，是針對部分來源網段回錯；Cloudflare 邊緣過得去。

## 2. 影響面盤點
- **前端即時報價**：仍活著（走 Worker proxy Yahoo，CF IP 沒被擋）。
- **GitHub Actions 靜態快照**：停更（`data/snapshot.json` 的 `fetchedAt` 卡在 15:50 那次成功）。
- **Worker `kind=imb`／`px1m`（D1）**：cron 的 `pollAndStore` 也打 Yahoo，Yahoo 對 CF 沒事，故大致正常。
- Worker 只有 `kind=tmf` 走期交所 OpenAPI，不依賴 Yahoo。

## 3. 修法與交付（v: scripts 層）
### 3.1 韌性（commit `ac6bc248`）
- `fetch_quote.get_list()`：加指數退避重試（原 4 次；涵蓋 5xx／逾時；4xx 除 429 直接拋）。
- 重試耗盡：**保留舊 snapshot、印 WARN、exit 0**（有舊檔才如此；首跑無舊檔才 raise），不寫壞資料、不中斷其他 step。
- `update-quote.yml`：`Fetch Yahoo WTX quote` 這步補 `continue-on-error: true`（第二層保險）。

### 3.2 借道自家 Worker（commit `3df95e94`，根本解）
- `fetch_quote` 的 `get_list()` 改**雙源**：① 直連 Yahoo（原主源）→ ② 失敗自動改走 `https://wtx.blok.trading/`（自家 CF Worker，proxy **同一支** stockList、**同格式**、回得到 WTX&／WCDF&／WCCF&）。
- 等於借道 Cloudflare IP 繞過 IP 選擇性 500。
- 直連優先 = 正常時行為不變（零風險）；僅 Yahoo 掛時才多一跳。
